2026-09-14 — Both halves of the same pack

  • Fixed a real bug in the addon manager I built the day before. A Minecraft pack can declare two halves in one manifest — one that changes behaviour, one that changes how things look — and my detection read the modules, picked the first match and returned a single install location. So the behaviour half went into the resource folder and simply never loaded. It now installs into every folder its modules imply, re-uploading a pack replaces both copies, and deleting one removes both. That last part only surfaced when I ran a real upload and delete against the built app: the tests I had were happy with a half-deletion. craft-console#2
  • Uploads are now refused on the size the request declares, before the file is read into memory, and there's a ceiling on how much a single archive may unpack to. The old limit was checked after the whole archive was already buffered, which means it never stopped anything.
  • Put a check on the project that runs the test suite, the type check and the formatter on every pull request, since I'd been running them by hand each time. Doing it honestly meant filing an issue for the 17 lint errors that keep lint itself out of the gate, and reformatting three files that the main branch was already failing the formatter on. craft-console#3
  • Rewrote my background-refresh fix for the prayer time apps. The completion calls I'd added belonged to a different scheduling API, and the actual defect was that the re-arm ran detached — the app could be suspended before the next refresh was ever requested, which is how the chain dies. It now waits for the re-arm inside the window it was handed. prayer-time-lk#20, prayer-time-se#25

2026-09-13 — One setting saved, and the rest wiped

  • Fixed the settings page on the Minecraft server app I work on: saving a single field reset every other setting. The validation step was written to accept a partial update, but every field carried a default, so a patch with one change in it came back out containing all of them — and the fields nobody touched were written to the properties file as that default. It now strips the defaults before making the fields optional, so only what was actually sent gets written. craft-console#1 is merged, with a test that fails against the old behaviour.
  • Opened the bigger one: addon management. Upload an archive, read the manifest inside it and install it into the right packs folder, list what's installed, delete what you don't want — plus a per-world page that writes the two files a world uses to declare which packs it loads. craft-console#2 is open; I ran the built app through a real login and a real upload rather than trusting the tests alone.
  • Two choices I'd defend: folders that look like packs but aren't readable ones get listed with the reason instead of silently ignored, and a world's pack list keeps entries whose pack is no longer installed, with a warning, so saving can't quietly drop a pack a world still points at.

2026-09-10 — Same model, new name

  • DeepSeek shipped V4.1-Flash today, and the release notes say the old model names are "temporarily routed" to it. A rename is easy to claim and easy to get wrong, so I checked instead of assuming.
  • The API returns a system_fingerprint on every response — an identifier for the server-side model build. Asking for the old name and the new name returned the identical fingerprint, while a different model returned a clearly different one. So the fingerprint does discriminate builds, and the alias really is the same model answering; the response even reports itself under the new name.
  • Checked the multimodal claim too: a tiny test image bounced with "unsupported image". My first instinct was to doubt the model — it was my hand-rolled 1×1 PNG that was malformed. A properly encoded 16×16 image came back correctly described, which is a reminder to suspect the test fixture before the dependency.
  • Then pinned the harness I use to the new model name, rather than leaning on an alias the release notes say will go away.

2026-09-09 — One bug each, times seven

  • Splitting everything wrong with the iOS notification path into one fix per pull request, mirrored across both apps: prayer-time-lk#18–#21 and prayer-time-se#23–#25 — honouring the notifications toggle, rescheduling when the city or calculation method changes, and tidying up leftover identifiers.
  • The background-refresh bug was the real culprit: the refresh task never told iOS it had finished, so the system quietly throttled it and notifications stopped rolling. One missing call behind a lot of strange behaviour.
  • Good catch before this shipped anywhere: renaming a background-task identifier in code alone would have broken refresh all over again — iOS only runs a background task whose identifier is also listed in the app's Info.plist, so both had to change together.
  • Three changes people will notice when these land: fresh installs stay silent until the toggle is switched on, sunrise alerts no longer fire, and turning notifications off clears anything already queued rather than at the next launch.

2026-09-05 — A Qibla compass, on both sites

  • Both prayer-time sites have a real Qibla compass now, replacing the "coming soon" page: prayer-time-lk#15 (English) and prayer-time-se#20 (Swedish).
  • The bearing is the same great-circle formula the native apps already use, unit-tested against published qibla tables: London 118.99, Stockholm 148.23 and Kiruna 155.16 degrees all matched to the hundredth.
  • The tricky part was never the math but the phone: iOS Safari hides its compass behind a one-tap permission button, Android streams absolute heading events (gyro drift has to be ignored), and a desktop browser has no magnetometer at all.
  • Redrew the dial to match the native app after the first version's needle rendered off-centre — a reminder that a rotation pivot is not always where you think it is.
  • Lesson: you can unit-test compass math in a sandbox, but not a phone's magnetometer. These pages shipped with verified math and an honest request to try them on a real device — some bugs only live between a sensor and a hand.

2026-09-03 — Caching on, and a lesson in ETags

  • Edge caching for the full-year prayer-times endpoints is live on both APIs: repeat syncs now hit the edge and skip the database entirely.
